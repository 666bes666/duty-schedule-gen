# Версии графика и файл проекта

Дата: 2026-10-10. Исходный коммит: f4326134433c9b1e8daca0a598cd88698920b9a0.

## Контекст и цель

Изменение реализует согласованный итог продуктового интервью; общий контракт:
[решения](../004-scheduling-validity/decisions.md). Baseline описывает наблюдения,
а не гарантии; уточняемые ID: UI-001, UI-002, EXP-001, EXP-002, EXP-004.

## Пользовательские сценарии

### US1 — Исправить и повторно открыть текущую версию (P1)

Ручная правка создаёт новую версию и pins, снимает валидность и отражается во всех представлениях. Сохранение/открытие сохраняет месяцы, часы и зависимости; forged ready, malformed changelog и неверный импорт не заменяют валидный проект.
Каждый сценарий связан с требованиями ниже и реальными тестами в traceability.

## Требования и критерии приёмки

- **REV-001**: Текущая версия едина для таблицы, календаря, статистики, экспорта и переноса. Правка создаёт новую версию и инвалидирует проверку; отдельное утверждение графика не требуется.
- **REV-002**: Версионированный переносимый файл сохраняет конфигурацию, полный календарь, версии, правки, подтверждения и историю; повторное открытие сохраняет назначения и часы. Некорректный файл не изменяет текущий проект.
- **REV-003**: Ручные назначения превращаются в пины и сохраняются при повторном расчёте до явного снятия; конфликт с запретом даёт диагностику, исходная версия сохраняется.
- **REV-004**: Экспорт разрешён после успешной повторной проверки текущей версии; подмена status/metadata во входном файле или API не обходит проверку.

## Границы и совместимость

Сохраняются Python 3.12+, uv и границы модулей. Существующие списки смен и команды
сохраняются; новые поля добавляются с миграцией старых настроек. Ошибочное старое
поведение (фиктивные отсутствия, приблизительная норма, непроверенный экспорт)
меняется намеренно. Устаревшие входы без календаря/истории допускают диагностику,
но не автоматически пригодный результат. Изменения API отражаются в контрактных
тестах и OpenAPI snapshot. Доказательства старых изменений не переписываются.

## Проверка успеха

Все перечисленные требования имеют воспроизводящие тесты в traceability;
обязательные проверки проходят, ограничения записаны в evidence. Зелёный SDD gate
сам по себе не доказывает выполнение требований. Complete устанавливается после
реализации, независимого ревью и проверки критериев.
