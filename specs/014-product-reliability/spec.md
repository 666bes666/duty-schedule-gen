# Сохранность данных и честные результаты действий

Дата: 2026-10-11. Статус: complete. Основание: [аудит 013](../013-product-logic-audit/audit.md), PLOG-01–05.
Это контракт следующей реализации; найденные дефекты пока существуют в runtime.

## Пользовательские сценарии

### US1 — Сохранить сотрудников и достоверную историю (P1)

Составитель импортирует данные, открывает таблицы и сохраняет их без изменений.
Никто не исчезает из XLS или редактора; скрытые счётчики истории не перезаписываются.
Неверный вход отвергается атомарно с указанием поля и действия для исправления.

### US2 — Получить честный результат проверки и эксперимента (P1)

Опечатка what-if не считается проведённым сценарием. Несовместимый календарь
не называется сбоем внешнего источника. Оптимизация показывает фактическое
изменение качества либо отсутствие данных о нём.

## Требования и критерии приёмки

- **DATA-001**: Непустое после strip отображаемое имя проверяется при вводе,
  загрузке и API до генерации. Допустимые имена с запятыми, кавычками и Unicode
  сохраняются точно. Неизменённый editor round-trip и XLS round-trip не меняют
  сотрудников, employee_id и историю. Ошибка строки XLS не считается молчаливым
  успешным концом команды; диагностируется строка/имя, текущий проект сохраняется.
- **DATA-002**: Неизменённая история сохраняет last_shift, as_of, source,
  consecutive_working/off/same_shift, no_previous_shifts и employee_id. Правка
  одного сотрудника не меняет остальных. Если правка делает скрытые счётчики
  несовместимыми, UI запрашивает их уточнение или помечает историю непроверенной;
  не придумывает 1 или 0. XLS → открыть «История» → сохранить без правок сохраняет
  все счётчики. Новый сотрудник по-прежнему подтверждается явно.
- **DATA-003**: UI и API проверяют один список допустимых путей what-if, включая
  вложенные Employee поля. Неизвестный путь получает ошибку с точным путём до
  запуска поиска; API использует native 422 для неверного patch. `{}` допустим
  как явно обозначенное отсутствие изменений; принятый параметр, не изменивший
  назначения, отличается от неподдерживаемого параметра. Legacy YAML `team_lead`
  проходит явную миграцию с видимым предупреждением о неподдерживаемом значении,
  а не молчаливое удаление; example продолжает загружаться. Другие неизвестные
  поля нового входа также не отбрасываются молча.
- **DATA-004**: Полный календарь во входной модели относится к Config.year/month.
  Несовпадение отвергается native 422 в API до генерации и до HTTP календаря;
  CLI validate завершается ненулевым кодом, UI сохраняет прежний проект и
  показывает несовместимые периоды. `/config/validate` не возвращает valid=true
  для такого тела. Реальный CalendarError внешнего источника сохраняет 502;
  прежние business 400, ready/diagnostic plan и export 409 сохраняются.
  Штатная смена месяца в UI остаётся допустимой операцией: до построения новой
  Config выбирается saved calendar нового периода либо None; старый календарь
  не переносится в новое тело и не делает само переключение ошибкой.
  Без полного календаря/свежей истории новый период остаётся неприготовленным.
- **DATA-005**: Результат действующей оптимизации различает `changes`,
  `no_changes`, `log_unavailable`. Для изменившихся назначений сохраняются
  алгоритм, ссылки на исходное/итоговое состояние, число изменённых ячеек и quality_key
  до/после с подписанными компонентами. Отсутствие changelog не доказывает
  отсутствие правок. UI показывает улучшившиеся/ухудшившиеся показатели и не
  обещает глобальный оптимум при ограниченном поиске. Реальные revision ID
  связываются после сохранения версии; отсутствующие ID не придумываются.

## Совместимость и границы

Живые контракты: SEC-002, HIST-002/003, UIC-001/003/004, HOURS-004.
Их ID сохраняются и дополняются критериями; этот контракт объединяет поставку
проверенных исправлений. Не меняются безусловные запреты, точная норма часов,
порядок качества первого расчёта и датированная история отдыха.

502 → 422 для несовместимого пользовательского календаря и запрет неизвестных
patch — намеренные исправления поведения. Legacy example и формат проектов
сохраняются через явную миграцию. При изменении OpenAPI schema обновляется snapshot
после анализа совместимости; тесты ошибок не заменяются snapshot.
