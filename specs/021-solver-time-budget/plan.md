# План

`scheduler/solver.py`: доля слоя вычисляется один раз (`layer_time_limit`). После
`solver.solve` первого слоя при `UNKNOWN`, отсутствии найденного графика и остатке
бюджета больше 0,01 с лимит временно равен `timeout − elapsed`, слой решается
повторно. После повтора каждый следующий слой получает `min(доля, остаток /
оставшиеся слои)`, а при остатке не больше 0,01 с цикл прекращается. Флаг `first_solution_retry` записывается
в metadata результата. Остальной цикл слоёв не меняется: FEASIBLE прерывает
улучшение, OPTIMAL фиксирует значение слоя.

Почему не перераспределять время всем слоям: это изменило бы качество и время уже
успешных расчётов и performance baseline. Повтор затрагивает только случаи, которые
сейчас заканчиваются `timeout` без решения, то есть результат не ухудшается.

Проверки. Unit `tests/unit/test_solver_time_budget.py` подменяет `CpSolver`
обёрткой, которая детерминированно возвращает UNKNOWN на выбранных вызовах и
записывает лимиты; тайминг CI на результат не влияет. Сохраняются существующие
solver/planning/system тесты. Стресс-скрипт вне репозитория сравнивает число ready
на одинаковых случайных конфигурациях до и после. Ruff, mypy, полный pytest с
coverage ≥ 80 %, SDD gate и индекс проекта.

Риски: повтор начинает поиск заново и тратит до полного бюджета на месяцы, где
решение не находится. Это ограничено прежним `timeout`; доказанно невыполнимые
месяцы возвращаются сразу, как раньше.
