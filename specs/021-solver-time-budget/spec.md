# Бюджет времени CP-SAT для первого решения

Дата 2026-10-19. Статус complete. Основание: поручение пользователя улучшить
проект и найденный при стресс-проверке дефект распределения времени решателя.

## Наблюдение

`solve_schedule` делит общий `timeout` поровну между лексикографическими слоями
(около семи). Если первый слой не находит ни одного решения за свою долю, поиск
завершается статусом `timeout`, хотя большая часть бюджета не потрачена. Greedy
вызывает восстановление через CP-SAT с `timeout=3`: первому слою достаётся около
0,43 с, и выполнимые месяцы получают диагностический черновик. Пример из стресс-
прогона: при `timeout=3` решатель останавливается через 0,53 с, при `timeout=10`
тот же месяц получает ready за 2–3 с.

## Сценарий

Составитель запускает расчёт трудного месяца (отпуска, графики 5/2, ограничения
смен). Greedy исчерпывает попытки и передаёт месяц CP-SAT. Решатель использует
весь отведённый бюджет, чтобы найти первое допустимое расписание, и только после
этого распределяет оставшееся время между слоями качества.

## Требования

- **BUDGET-001**: Если первый слой не нашёл решения в своей доле (статус UNKNOWN)
  и бюджет не исчерпан, тот же слой повторно ищет решение с остатком бюджета.
  Сумма лимитов не превышает `timeout`. Если остаток тоже исчерпан без решения,
  результат по-прежнему имеет статус `timeout` и диагностический черновик.
  Приёмка: смоделированный UNKNOWN первого вызова даёт второй вызов с лимитом
  `timeout − доля` и ready; двойной UNKNOWN даёт `timeout` в пределах бюджета.
- **BUDGET-002**: Остальное поведение не меняется. Если решение найдено в доле,
  все слои используют прежнюю долю. UNKNOWN последующего слоя не повторяется,
  лучший найденный график сохраняется. Доказанная невыполнимость (INFEASIBLE)
  возвращается сразу без повтора. Приёмка: лимиты всех вызовов равны доле.
- **BUDGET-003**: `metadata.first_solution_retry` показывает, использовался ли
  повтор. Различие infeasible/timeout/heuristic_exhausted из VALID-004 сохраняется.
  Приёмка: флаг true при повторе и false без него.

## Границы

Модель ограничений, порядок и состав слоёв, значение `SOLVER_TIMEOUT_S`, API, CLI,
UI и формат проекта не меняются. Новых зависимостей нет. CP-SAT с лимитом по
wall time остаётся зависимым от скорости машины; изменение уменьшает этот эффект
для первого решения, но не делает поиск детерминированным по времени.
