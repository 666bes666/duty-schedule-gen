Изменение реализует согласованный итог продуктового интервью; общий контракт:

## Пользовательские сценарии

### US1 — Получить именно проверенную поставку (P1)

CP-SAT реально исполняет обязательные регрессии без skips; installed wheel и container выполняют API/UI journey. Восстановленный priorSHA benchmark сравнивается до promotion; release публикует проверенные bytes того же sourceSHA/version после gates.
Каждый сценарий связан с требованиями ниже и реальными тестами в traceability.

## Требования и критерии приёмки

- **DEL-001**: CI отдельно устанавливает и проверяет CP-SAT без допустимого пропуска; регрессии обязательных правил выполняются в поставляемых режимах. Покрытие не ниже 80%.
- **DEL-002**: Детерминированные пользовательские проверки выполняют импорт, генерацию, правку, проверку, скачивание и повторное открытие проекта; installed wheel и контейнер API/UI выполняют функциональный smoke.
- **DEL-003**: Бенчмарк нового SHA сравнивается с реально восстановленным предыдущим успешным baseline; порог означает 10% замедления, провалившийся запуск не становится baseline.
- **DEL-004**: Релиз зависит от успешных gates конкретного SHA; проверяется та же собранная поставка, которая публикуется с checksum. Создание тега через GITHUB_TOKEN не предполагает запуск другого workflow.

Уточнение DEL-003: новый namespace benchmark-v2 первоначально может не иметь
валидного priorSHA. Первый успешный запуск устанавливает baseline; это bootstrap,
а не доказательство сравнения. После появления baseline совпадение restore-prefix
без exact cache-hit тоже обязательно включает сравнение. Failed-run не продвигается.

## Границы и совместимость

Сохраняются Python 3.12+, uv и границы модулей. Существующие списки смен и команды
сохраняются; новые поля добавляются с миграцией старых настроек. Ошибочное старое
поведение (фиктивные отсутствия, приблизительная норма, непроверенный экспорт)
меняется намеренно. Устаревшие входы без календаря/истории допускают диагностику,
но не автоматически пригодный результат. Изменения API отражаются в контрактных
тестах и OpenAPI snapshot. Доказательства старых изменений не переписываются.

## Проверка успеха

Все перечисленные требования имеют воспроизводящие тесты в traceability;
обязательные проверки проходят, ограничения записаны в evidence. Зелёный SDD gate
сам по себе не доказывает выполнение требований. Complete устанавливается после
реализации, независимого ревью и проверки критериев.



## Уточнение DEL-001 от 2026-10-13 — macOS native PDF

Во время разрешённого продвижения до main оба macOS задания Python3.12/3.13
завершилисьSIGSEGV при CFFI загрузке WeasyPrint в Streamlit AppTest. DEL-001
теперь явно требует подготовки нативных PDF библиотек и пути загрузки до
матрицыmacOS, с обязательной реальной генерациейPDF до pytest. Проверка не
заменяет существующие unit/E2E/UI/platform/installed/container gates и не вводит
skip/xfail. Критерий: native smoke и полный macOS pytest проходят в обеих версиях;
остальные платформы и требованияDEL-002..004 сохраняются. Продуктовые API/UI
контракты не меняются.

## Уточнение DEL-003 от 2026-10-16 — сопоставимые замеры

Повторный CI Test 38921853888 подтвердил 10–11% разницу при неизменном scheduler:
runner AMD EPYC сравнивался с сохранёнными замерами Intel Xeon. Восстановленный
успешный baseline остаётся источником предыдущего SHA, но его времена повторно
измеряются на текущем runner перед сравнением с текущей версией. Обе версии
используют один Python interpreter и собственные frozen uv.lock окружения.

Критерии DEL-003: сравнение использует свежий результат именно выбранного prior
SHA; отсутствующий commit, ошибка исполнения, отсутствие нового отчёта или другой
SHA в нём останавливают gate. Порог mean:10%, ready assertions и продвижение только
после всех gates сохраняются. Bootstrap допустим только без валидного предыдущего
baseline, как раньше. Невалидный Git SHA не исполняется. Текущий checkout и его
окружение не переключаются; временный checkout удаляется после успеха и ошибки.
Функциональная приёмка: реальный повторный замер восстановленного prior SHA и
сравнение текущей версии на одной машине, плюс отрицательные регрессии.
