# Наблюдаемые ограничения baseline

Зафиксированы при аудите исходного коммита `949b6bc53ba649d496d130545acb81a8dc6f656d` от 2026-10-10. Это реестр расхождений и границ свидетельств, а не список принятых требований к новому поведению.

1. **Разные лимиты рабочих серий.** Исходный README заявлял значение по умолчанию 5. Модель хранит `None`, планирование использует 6, а часть стадий greedy-постпроцессинга — 5. Это явно закреплено в [test_max_consecutive_constants.py](../../tests/unit/test_max_consecutive_constants.py). Превышения в финальной проверке мягкие. Источник: [constraints.py](../../src/duty_schedule/scheduler/constraints.py), [validation.py](../../src/duty_schedule/scheduler/postprocess/validation.py).

2. **Отличия CP-SAT от greedy.** CP-SAT не читает `config.seed`, `carry_over`, `optimization_priority`, `always_on_duty` и не возвращает carry-over metadata. При FEASIBLE решение принимается без доказательства оптимальности. Тесты solver проверяют построение, покрытие и города; greedy-тесты воспроизводимости и межмесячной непрерывности не доказывают аналогичного поведения solver. Источник: [solver.py](../../src/duty_schedule/scheduler/solver.py), [test_solver.py](../../tests/unit/test_solver.py), [test_determinism.py](../../tests/system/test_determinism.py).

3. **Длительность ночного ICS-события.** `_shift_times` ставит конец ночи на следующую дату, хотя начало — 00:00 исходной даты. Получается 32 часа, тогда как README описывал ночь 00:00–08:00. Тесты `test_night_shift_ends_next_day` и `test_night_shift_rollover_across_year_boundary` закрепляют текущую дату окончания. Изменение требует отдельного решения о временной модели. Источник: [ics.py](../../src/duty_schedule/export/ics.py), [test_ics_per_employee.py](../../tests/unit/test_ics_per_employee.py).

4. **Перенесённые рабочие выходные.** Даже если сервис календаря отмечает субботу рабочей, scheduler считает любой день недели 5 или 6 выходным. Норма также считает только понедельник–пятницу вне множества праздников. Полный официальный производственный календарь таким представлением не воспроизводится. Источник: [calendar.py](../../src/duty_schedule/calendar.py), [constraints.py](../../src/duty_schedule/scheduler/constraints.py), `_is_weekend_or_holiday`, `_calc_production_days`.

5. **Неодинаковые проверки точек входа.** CLI, UI и API вызывают разные комбинации проверок. В финальной проверке блокированные даты и длинные серии мягкие, покрытие, дубли рабочих смен, вечерний отдых, 5/2 в выходные и сохранение пинов жёсткие. Редактор UI проверяет только часть ограничений и не блокирует экспорт при каждом показанном нарушении. Источник: [cli.py](../../src/duty_schedule/cli.py), [builders.py](../../src/duty_schedule/ui/builders.py), [validation.py](../../src/duty_schedule/scheduler/postprocess/validation.py), [app.py](../../app.py).

6. **Слабая сквозная проверка UI.** Тест с названием export download проверяет лишь HTTP 200. Тест generation проверяет наличие кнопки. Сценарии фактической генерации, скачивания XLSX/ICS/PDF, импорта YAML, ручной правки и истории в браузере не проверены этим набором. Источник: [tests/ui](../../tests/ui/). Модульные тесты конфигурации и diff не заменяют эти сценарии.

7. **Совместимость и правовые утверждения.** Структура XLSX и формулы проверены через openpyxl; запуск Excel 2016 и пересчёт формул не проверены. PDF-тесты не подтверждают визуальную пригодность для печати всех команд. Арифметические тесты множителей не доказывают соответствие всем нормам ТК РФ. Источник: [test_export_format_contract.py](../../tests/contract/test_export_format_contract.py), [test_pdf_export.py](../../tests/unit/test_pdf_export.py), [test_costs.py](../../tests/unit/test_costs.py).

8. **OpenAPI описывает только часть HTTP-контракта.** В генерируемой схеме операции объявляют 200/422; прочие runtime-коды, заголовки rate limit и часть бизнес-проверок отсутствуют. Бинарные экспорты описаны как JSON. Схема безопасности содержит APIKeyHeader, хотя runtime поддерживает Bearer. Business 422 одиночной генерации содержит строки, а документированный HTTPValidationError — объекты ошибок. Поэтому [contracts/openapi.json](contracts/openapi.json) является снимком схемы для обнаружения изменений, а не полной спецификацией runtime.

9. **Непокрытые API-краевые случаи.** POST `/api/v1/schedule/generate-range` с `config={}` возвращает 500; обратный диапазон возвращает 200 с пустым `schedules`. Диапазон и PDF зарегистрированы, но исходные endpoint-тесты не обращаются к ним. Эти факты получены API-аудитом реализации и отдельными runtime-пробами, а не существующим контрактным набором. Источник: [schedule.py](../../src/duty_schedule/api/routes/schedule.py), [export.py](../../src/duty_schedule/api/routes/export.py).

10. **Аутентификация и префикс в документации.** Исходный README указывал auth default `false` и маршруты без `/api/v1`; действующая конфигурация использует `True`, маршруты имеют префикс. Лимитер в памяти процесса не обеспечивает единый лимит нескольких процессов. Публичные docs не означают публичную генерацию. Источник: [settings.py](../../src/duty_schedule/api/settings.py), [api/__init__.py](../../src/duty_schedule/api/__init__.py), [ratelimit.py](../../src/duty_schedule/api/ratelimit.py).
