# Достоверная история между месяцами

Дата: 2026-10-10. Исходный коммит: f4326134433c9b1e8daca0a598cd88698920b9a0.

## Контекст и цель

Изменение реализует согласованный итог продуктового интервью; общий контракт:
[решения](../004-scheduling-validity/decisions.md). Baseline описывает наблюдения,
а не гарантии; уточняемые ID: SCH-006, SCH-007, EXP-005.

## Пользовательские сценарии

### US1 — Продолжить график через границу месяца (P1)

Вечер последней даты ограничивает утро/Р следующей, смешанная рабочая серия не обнуляется. Сохранённый/импортированный месяц сохраняет дату и счётчики; range останавливается на первом diagnostic с сохранением ready предшественников.
Каждый сценарий связан с требованиями ниже и реальными тестами в traceability.

## Требования и критерии приёмки

- **HIST-001**: Оба алгоритма и финальная проверка учитывают предыдущую смену и рабочую серию; вечер→утро/Р и восьмой рабочий день запрещены через границу месяца.
- **HIST-002**: История хранит идентичность сотрудника, дату состояния и источник; допускается ручной ввод и явное отсутствие предыдущих смен. Отсутствующая или устаревшая история не подменяется нулём для ready.
- **HIST-003**: Перенос считает смешанную рабочую серию отдельно от серии одинаковых смен; экспорт/импорт сохраняют счётчики и период, неизвестные ячейки не превращаются молча в выходные.
- **HIST-004**: Многомесячный расчёт сохраняет успешно проверенные месяцы, добавляет первый диагностический и останавливается. Перенос следующего месяца вычисляется из текущей проверенной версии.

## Границы и совместимость

Сохраняются Python 3.12+, uv и границы модулей. Существующие списки смен и команды
сохраняются; новые поля добавляются с миграцией старых настроек. Ошибочное старое
поведение (фиктивные отсутствия, приблизительная норма, непроверенный экспорт)
меняется намеренно. Устаревшие входы без календаря/истории допускают диагностику,
но не автоматически пригодный результат. Изменения API отражаются в контрактных
тестах и OpenAPI snapshot. Доказательства старых изменений не переписываются.

## Проверка успеха

Все перечисленные требования имеют воспроизводящие тесты в traceability;
обязательные проверки проходят, ограничения записаны в evidence. Зелёный SDD gate
сам по себе не доказывает выполнение требований. Complete устанавливается после
реализации, независимого ревью и проверки критериев.


## Уточнение после аудита и интервью 013 — 2026-10-11

HIST-002/003 дополнены сохранностью полных счётчиков и source при неизменённом сохранении UI history и правке одного сотрудника. Допустимые display names не теряют сотрудника в XLS; неизвестная строка не считается успешным концом импорта. Это DATA-001/002 изменения 014; история качества из 017 отделена от обязательного carry-over отдыха.

Контракт после уточнения реализован вместе с 014–017. Результаты прежней реализации
сохранены в evidence; новые selectors проверены, результаты добавлены отдельно. Связи:
014 сохранность → 015 подготовка/восстановление → 016 repair → 017 качество.
