# Составление графика в интерфейсе

Дата: 2026-10-10. Исходный коммит: f4326134433c9b1e8daca0a598cd88698920b9a0.

## Контекст и цель

Изменение реализует согласованный итог продуктового интервью; общий контракт:
[решения](../004-scheduling-validity/decisions.md). Baseline описывает наблюдения,
а не гарантии; уточняемые ID: CFG-001, CFG-002, CFG-003, CFG-004, UI-001, UI-002.

## Пользовательские сценарии

### US1 — Использовать проверяемый результат (P1)

Один ответственный составитель применяет возможности этого изменения и видит
пригодный график либо конкретную диагностику. Каждый критерий ниже проверяется
воспроизводящим примером, а не только наличием поля/кнопки.

## Требования и критерии приёмки

- **UIC-001**: YAML использует типизированную конфигурацию, round-trip сохраняет solver, timezone, carry-over и новые поля. Неверный импорт не меняет состояние; пустая команда не подменяется демонстрационной.
- **UIC-002**: Составитель задаёт больничный/отпуск, выбранную норму, историю, конкретные подтверждения, часы Р; может сохранить/открыть проект, снять пин и рассчитать реальный диапазон месяцев.
- **UIC-003**: Все представления используют текущую версию; диагностические причины и запросы подтверждений видны, обычные кнопки экспорта доступны только для проверенного графика.
- **UIC-004**: What-if поддерживает одинаковые изменения в UI/API; смена периода выполняется сценарием диапазона с соответствующим календарём, прежний календарь не используется для другого периода.

## Границы и совместимость

Сохраняются Python 3.12+, uv и границы модулей. Существующие списки смен и команды
сохраняются; новые поля добавляются с миграцией старых настроек. Ошибочное старое
поведение (фиктивные отсутствия, приблизительная норма, непроверенный экспорт)
меняется намеренно. Устаревшие входы без календаря/истории допускают диагностику,
но не автоматически пригодный результат. Изменения API отражаются в контрактных
тестах и OpenAPI snapshot. Доказательства старых изменений не переписываются.

## Проверка успеха

Все перечисленные требования имеют воспроизводящие тесты в traceability;
обязательные проверки проходят, ограничения записаны в evidence. Зелёный SDD gate
сам по себе не доказывает выполнение требований. Complete устанавливается после
реализации, независимого ревью и проверки критериев.
