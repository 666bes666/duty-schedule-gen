# Единый состав с автосохранением

Дата2026-10-13. Статус in-progress. Основание: approve интервью grill-me и отдельное поручение
реализовать. Заменяет UI шагов018 и очередь/профили019; прочие проверки/правила сохраняются.

## Сценарий

Первый экран нового проекта — «1. Состав», пустая редактируемая таблица без шага0,
примеров имён и ролей. Пользователь добавляет строку, указывает имя/город/график/дежурство
в её ячейках. Добавление, редактирование, удаление и копирование фиксируются автоматически.
Копирование переносит все столбцы состава, очищает имя и создаёт новый ID; даты отсутствия,
история и закрепления исходного сотрудника не копируются. Состав готовится в этом же экране.

## Требования

- **ROSTER-001**: Новый проект сразу показывает «1. Состав» с нулём сотрудников; нет
  вкладки0, отдельной очереди/профилей или кнопок применения сотруднику/группе. Новая
  строка не подставляет имя, город, график и участие. Все четыре поля явно задаются в
  таблице; 5/2 и участие остаются независимыми. Приёмка: заполнить команду в таблице
  и перейти к календарю/истории/первому расчёту без этапа внесения персонала.
- **ROSTER-002**: Копировать выбранную строку одной кнопкой; новый уникальный ID, пустое
  имя, все настройки столбцов (включая скрытые особые условия) сохранены. История,
  отпуск/больничный/недоступность и pins не копируются. Несколько копий не конфликтуют;
  исправление имени не меняет ID; удаление адресовано ID.
- **ROSTER-003**: Каждая завершённая правка ячейки/добавление/копирование/удаление/период
  автоматически сохраняется без submit. Незавершённая строка, повтор имени, пустое имя
  и несовместимые условия сохраняются как черновик и восстанавливаются после reload
  и backup/import. Ошибки показаны рядом с таблицей с номером строки/именем; пустой либо
  ошибочный состав блокирует любой расчёт (включая диагностический), и экспорт старого
  результата не выдаёт себя за результат новых настроек. Ошибка не затирает данные.
- **ROSTER-004**: Старые projectJSON/YAML и personnel_draft version1 открываются в едином
  составе, сохраняя ID, явные роли, спецполя, датированные отсутствия, историю, версии,
  календарь и подтверждения. Старый stage игнорируется в представлении. Новый browser
  backup roster_draft version1 хранит таблицу и действующий проект атомарно; публичные
  serializer проекта, API и CLI не меняются. Неизвестный/повреждённый import не заменяет
  состояние. Browser conflict/quota/previous backup не теряются.
- **ROSTER-005**: Один editor для нового и существующего проекта. Изменение корректной
  таблицы обновляет Config с ID-based переносом ограничений/ссылок, смена периода
  использует сохранённый календарь соответствующего месяца. Некорректная таблица не
  подменяется последним Config и не запускает расчёт. Клавиатурный ввод/375px работают,
  особые условия раскрываются по запросу, название «Только дежурства» сохраняется.

## Границы

Без новых зависимостей, без изменения solver/API/CLI/публичного projectJSON. Нативный
Streamlit editor и существующая тема. Автосохранение происходит при commit ячейки
(Enter/Tab/потеря фокуса), а не на каждый символ. Копируется таблица, не личная история.
