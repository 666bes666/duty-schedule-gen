# UX аудит и анализ до реализации

На localhost:8504 проверен существующий проект без изменения его данных: состав,
полный широкий редактор, сортировка и три дополнительных кнопки конкурируют; готовность
находится ниже вкладок. В шаге 1 исходники показывают два одинаково заметных пути
(персональный и групповой), group содержит уже настроенных. Чёрный текст autosave
iframe не наследует тёмную тему родителя.

ui-ux-pro-max: design-system search и UX search выполнены до разработки. Применяем
progressive disclosure, bulk actions, feedback near action, native inputs. Landing hero,
новая палитра/шрифты и миграция React Native не подходят существующей рабочей форме.
Структура пути: 0 персонал/период → 1 явные роли → готовность/календарь/реальная история →
расчёт → проверка/результат/экспорт. Необязательные ограничения/пины/подтверждения доступны
и не становятся обязательными кликами. Backup остаётся рядом, а не в начале сценария.

Каждый UX ID имеет тестовую связь. UX-001/002 дополняют STAFF-003 без отмены независимости
полей. UX-004 не вводит новый hard rule: WORKDAY уже запрещён для always_on_duty и
morning/evening_only; валидатор требует московского дежурного с morning/evening_only.
UX-003 не скрывает ошибки и не подменяет календарь/историю. Scope точный, API не меняется.
Анализ: противоречий и существенных неизвестных не обнаружено; реализация разрешена.

## Уточнение после browser регрессии

Три сбоя: детали готовности теперь раскрываются по запросу (тест должен раскрыть их),
полный пересчёт скрыт в расширенном расчёте (тест должен раскрыть), результат теряет
активную вкладку после асинхронного rerun (требуется stateful selection независимо
от версии). UX-003 уточнён, scope тестов расширен до исправления. Stateful result tabs
сохраняют доступ к редактированию; правила ручных назначений/экспорта не меняются.
