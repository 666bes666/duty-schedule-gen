# Комплексный аудит, обязательный SDD и холодный старт

Дата: 2026-10-11. Исходный коммит: f5ae141bffde227e7f005052832b87de8595dc37.
Поручение: комплексный аудит всего проекта, строгая разработка по SDD, удаление
подтверждённого мусора/legacy, индексирование, холодный старт и доставка из dev
через GitHub. Конституция, руководство, реализация, тесты и CI изучены до изменения.

## Пользовательские сценарии

### US1 — Изменять проект только через контракт (P1)

Разработчик готовит требования, план, задачи и traceability. Попытка изменить код,
тесты, зависимости, CI, настройки или правила без связанной спецификации
блокируется локально и в CI. Простое прикладывание посторонней спецификации
не покрывает файлы вне её явно объявленной области.

### US2 — Продолжить работу с нуля (P1)

Новый составитель/агент открывает чистый clone, восстанавливает locked окружение,
получает актуальные пути, модули, требования, тесты, API и состояние Git одной
командой. Проверка обнаруживает устаревший индекс. Никакие локальные указатели,
старые /tmp окружения или память другого чата для этого не требуются.

### US3 — Использовать проверенную актуальную систему (P1)

Аудит проверяет все подсистемы и артефакты; найденное старое дублирование удаляется
с сохранением полезных проверок действующего поведения. Результаты, ограничения
и фактические GitHub gates зафиксированы, а исторические evidence сохранены.

## Требования и критерии приёмки

- **AUD-001**: Все изменения вне самих SDD-артефактов, включая новые, удалённые и
  переименованные файлы, требуют изменённого planned/in-progress/complete контракта
  с точным списком `files`. Непокрытый файл, baseline, draft и удалённый artifact
  не удовлетворяют gate. `--base` видит рабочее дерево, staged и untracked;
  `--staged` проверяет именно индекс Git, а не подменяющие его unstaged документы.
- **AUD-002**: Требования спецификации и traceability совпадают в обоих направлениях;
  задачи имеют уникальные T-ID; test selectors обозначают собираемые test функции.
  Пустой/невалидный файл теста, вложенный helper, пустая область или путь за пределами
  репозитория отвергаются. Complete требует закрытых задач, реальных тестов,
  evidence и записи приёмки по каждому ID. Все существующие контракты мигрированы.
- **AUD-003**: Конституция, AGENTS, CLAUDE, CONTRIBUTING, шаблоны и CI прямо
  запрещают реализацию вне SDD, включая hotfix, refactor, docs, test и CI.
  Pre-commit проверяет staged diff; SDD CI не использует feature.json и проверяет
  drift индекса. Технические gates не заявляются доказательством смысла требований.
- **AUD-004**: Детерминированный индекс включает все версионируемые и новые
  неигнорируемые файлы, Python symbols/imports, спецификации/требования/test mappings,
  workflow и OpenAPI операции. Генерация не исполняет исходники, не читает secrets
  и не включает local/ignored артефакты. `--check` отвергает drift.
- **AUD-005**: Холодный старт описан и проверен в отдельном чистом clone с новым
  окружением: locked sync, context, SDD, индекс и целевые регрессии. Context
  показывает live branch/SHA/dirty и выбранную спецификацию без записи feature.json.
- **AUD-006**: Удалены подтверждённо неиспользуемый построитель `_build_day` и
  вспомогательные селекторы и неиспользуемый `_shift_limit_reached`; его полезные сценарии проверяют действующий
  `build_candidate`. Удалён архив комментариев NOTES; ARCHITECTURE отражает v5.
  Поддерживаемые календарные/history migration adapters и проверяемый pipeline
  сохраняются с объяснением назначения. API/OpenAPI и форматы продукта сохраняются.
- **AUD-007**: Аудит охватывает scheduler/models/calendar/history/project/API/CLI/UI/
  exports/dependencies/toolkit/CI/docs. Обязательные проверки и покрытие >=80%
  проходят; evidence отличает выполненные проверки от ограничений. SDD добавлен
  к обязательным GitHub checks; устаревшие check names исправлены без ослабления
  review policy. Продвижение dev→test→main выполняется PR через GitHub при зелёном CI.

## Совместимость и границы

Изменяется контракт разработки (конституция 1.1.0), а не бизнес-правила v5.
Приватный `_build_day` и `_select_*` больше не являются поддерживаемой альтернативой
генератору. Public generate/plan/revision/export, модели и CLI сохраняются.
Baseline — историческое наблюдение; живые 003–011 контракты приоритетны для v5.
Исторические evidence не удаляются. Правила GitHub, недоступные без прав/approving
review, обозначаются ограничением доставки; администраторский обход не применяется.
Аудит не обещает математическое доказательство отсутствия всех дефектов, проверку
Excel2016 или правовое подтверждение расчётов стоимости.

## Приёмка

Негативные тесты воспроизводят обходы SDD, положительные проверяют рабочий процесс.
Полный pytest/coverage, UI, security, сборка/installed smoke и GitHub platform gates
проверяют сохранение продукта. Проверяемый отчёт: `audit.md`, результаты: `evidence.md`.
