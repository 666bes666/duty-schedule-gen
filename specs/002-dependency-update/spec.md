# Обновление зависимостей

**Каталог**: specs/002-dependency-update
**Ветка реализации**: dev
**Дата**: 2026-10-10
**Статус**: in-progress
**Запрос**: обнови зависимости

## Сценарии и приёмка

### US1 — Снять блокер аудита (P1)

Разработчик обновляет зависимости и получает воспроизводимое окружение без
известных уязвимостей, обнаруженных текущим аудитом.

1. При аудите исходного окружения воспроизводится отчёт: 78 находок в 10 пакетах.
2. После обновления аудит базового окружения с security-инструментами проходит;
   дополнительные solver/UI/performance группы также проверены отдельно.
3. Существующие security-проверки сохраняют способность отклонять уязвимости.

### US2 — Сохранить работоспособность продукта (P1)

Пользователь продолжает создавать график и пользоваться программными интерфейсами
и экспортом после обновления библиотек.

1. Существующие контрактные, системные и интеграционные тесты проходят.
2. Структура программного интерфейса сохраняется; изменение схемы не принимается
   простым перезаписыванием снимка без объяснения.
3. Проверены обычная установка, optional solver, сборка и запуск интерфейса.
   Недоступные платформенные библиотеки фиксируются как пропуски.

## Требования

- **DEP-001**: доступные стабильные зависимости обновлены в пределах совместимости
  проекта; окружение воспроизводится из фиксированных версий, поддержка Python
  3.12+ и действующих платформ сохраняется.
- **DEP-002**: свежий аудит не обнаруживает известных уязвимостей в проверенных
  базовом и расширенном окружениях. Игнорирование advisory или отключение
  security gate не является выполнением требования.
- **DEP-003**: программные интерфейсы, форматы конфигурации, генерация и экспорт
  сохраняют проверенное поведение; необходимые адаптации ограничены совместимостью.
- **DEP-004**: проверки качества, сборка и CI для dev и PR проходят после обновления;
  покрытие пакета не ниже 80%, фактические результаты и пропуски записаны.
- **DEP-005**: обычная установка не разрешает прямые зависимости в известных
  уязвимых версиях, исправленных в этой работе; инструменты проверки согласованы
  между локальным окружением и hook.

## Граничные случаи

- Новая версия несовместима с другой зависимостью: выбирается совместимая стабильная
  версия, причина и пределы записываются; новые несовместимые ограничения не скрываются.
- Обновление меняет схему или поведение: различить необходимую адаптацию и отдельный
  дефект продукта; сохранить тесты исходного контракта и добавить регрессию при нужде.
- Аудит пропускает локальный unpublished пакет: его внешние зависимости всё равно
  проверяются; сообщение о пропуске не выдаётся за аудит самого исходного кода.
- Недоступная optional/native проверка явно отделена от пройденной.

## Успех и допущения

Ноль известных уязвимостей в свежем аудите проверенных окружений, зелёные обязательные
проверки и отсутствие необъяснённого изменения контрактов. Аудит отражает доступную
базу advisory на момент проверки, а не гарантию отсутствия всех возможных дефектов.

Запрос относится к Python-зависимостям проекта и связанному lint hook. Spec Kit,
GitHub Actions и версия приложения не обновляются как самостоятельные продукты.
Продвижение в main и выпуск релиза не входят в обновление зависимостей.
