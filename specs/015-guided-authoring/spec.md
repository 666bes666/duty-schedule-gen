# Подготовка графика и сохранение работы составителя

Дата: 2026-10-11. Статус: planned. Основание: ответы 1/2/5
[интервью 013](../013-product-logic-audit/spec.md), PLOG-09 и UX аудит.

## Пользовательские сценарии

### US1 — Подготовить данные и получить первый месяц (P1)

Составитель видит готовность состава, календаря, истории, отсутствий и pins.
Каждая проблема указывает следующее действие. Для штатного первого расчёта
не требуется выбирать имя solver/seed/timezone или вручную писать JSON.

### US2 — Продолжить работу после перезагрузки (P1)

Приложение восстанавливает последний успешно сохранённый проект в том же браузере.
Резервный JSON можно скачать и открыть явно. Excel/PDF предназначены для выдачи.

## Требования и критерии приёмки

- **FLOW-001**: Основной путь подготовки показывает состояние пяти групп:
  состав/доступность, полный календарь, обязательная история отдыха, pins и нормы.
  Каждая блокирующая причина имеет сотрудника/дату/поле, объяснение и переход
  к редактированию. Неполные данные не запускают бесполезный обычный поиск;
  диагностическое исследование доступно отдельно и не выдаётся за ready.
  Новый сотрудник подтверждается явно; неизвестная история не заполняется нулём.
- **FLOW-002**: Каждая применённая валидная операция проекта автоматически
  сохраняется в этом браузере. После подтверждения сохранения reload/закрытие
  и повторное открытие восстанавливают месяцы, выбранный период, revisions,
  назначения/часы, pins, approvals, нормы, календарь и историю. Восстановление
  проходит load_project и повторную проверку, сохранённый ready не доверяется.
  Неотправленные формы обозначаются как неприменённые; это не сохранённая версия.
- **FLOW-003**: UI различает «есть неприменённые правки», «сохранение идёт»,
  «сохранено», «ошибка сохранения». Повреждённая/неподдерживаемая запись и отказ
  browser storage не уничтожают открытый проект или последний корректный snapshot;
  доступны повтор записи и скачивание резервного JSON. Две вкладки не перезаписывают
  молча более новую версию одного проекта; конфликт предлагает сохранить копию.
  Хранение привязано к браузеру/origin и project ID; синхронизация устройств
  и серверное хранение не обещаются.
- **FLOW-004**: Первый расчёт показывает отдельно исправимые причины данных,
  нехватку подходящих сотрудников, запрос конкретного разрешённого подтверждения
  и ограниченность поиска. Корневые причины предшествуют повторным следствиям;
  доступен полный список. Результат и следующая доступная операция объясняются
  без требования понимать технический код. Solver/seed доступны в дополнительных
  настройках; фиксированные часовые правила из 004 не представлены как произвольно
  изменяемая временная модель. Тест с реалистичным saved calendar/history без
  pins на все ячейки проходит подготовку → расчёт → правку → проверку → выдачу
  → reload без потерь и без работы с JSON в штатном UI пути.

## Совместимость и границы

Основной источник — текущая версия проекта приложения. Существующий импорт
carry-over из XLS, YAML и явный JSON сохраняются. Старые проекты без browser
backup открываются штатно; server database/accounts не добавляются. Сначала 014
устраняет потери и неверную валидацию; затем данный приоритетный UX путь.
Нормы, hard rules и approvals не ослабляются ради удобства.

## Приёмка

Unit storage adapter checks и реальные Playwright journeys: reload/reopen,
повреждённое хранилище, отказ записи, две вкладки, valid/invalid import и независимый
первый расчёт. Browser-test не должен подменять весь расчёт заранее pinned месяцем.
Время пути пока не объявляется числом без наблюдения реального составителя;
обязательные проверяемые критерии — сохранность и отсутствие служебных операций.
